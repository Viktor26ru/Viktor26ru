# Протокол инвайтов (invite-only) — практическая спецификация

## Цели

- Нельзя найти пользователя по логину/телефону/нику.
- Добавление контакта только по валидному приглашению.
- Защита от перебора и повторного использования токена.

## Формат токена

Токен не содержит открытых персональных данных. Рекомендуемый формат:

`inv1.<random_192_bit>.<sig>`

Где:
- `random_192_bit` — криптостойкий nonce.
- `sig` — серверная подпись (HMAC/EdDSA) по nonce + expiry + policy.

На сервере хранить только `token_hash` (Argon2id/SHA-256 + salt), а не токен в открытом виде.

## Жизненный цикл

1. Issuer создаёт инвайт (`POST /invites`) с TTL и max_uses=1.
2. Токен передаётся по QR/ссылке/out-of-band каналу.
3. Recipient отправляет токен на `POST /invites/redeem`.
4. Сервер проверяет:
   - подпись токена,
   - не истёк ли TTL,
   - `uses_count < max_uses`,
   - anti-abuse лимиты.
5. Если валиден — сервер атомарно:
   - увеличивает `uses_count`,
   - помечает как использованный,
   - создаёт запись в `contacts`.
6. Оба клиента получают событие `invite.redeemed` через websocket.

## Атомарность и гонки

Использовать транзакцию + `SELECT ... FOR UPDATE` по записи invite.

Псевдологика:

1) lock invite row
2) validate expiry/uses/revoked
3) increment uses
4) create contact edge if absent
5) commit

Это исключает двойное использование при гонках.

## Анти-сканирование

- TTL по умолчанию: 10 минут.
- Single-use всегда для персональных инвайтов.
- Лимит создания инвайтов: например 20/сутки на пользователя.
- Лимит redeem: 10 попыток/час на устройство + IP risk score.
- Временная блокировка при аномальном числе невалидных попыток.

## UX-рекомендации

- Кнопка «Пригласить контакт» генерирует QR + короткую ссылку.
- Отображать понятные статусы:
  - «Инвайт истёк»
  - «Инвайт уже использован»
  - «Подозрительная активность, попробуйте позже»
- В чате системное сообщение «Контакт добавлен по приглашению».

## Безопасность

- Не включать `issuer_user_id` в открытый payload токена.
- Ограничивать логи: не писать полный токен в логи никогда.
- В аналитике хранить агрегаты, а не сырые токены.
- Добавить rotation server keys для подписи invite.
