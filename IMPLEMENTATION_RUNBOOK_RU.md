# Implementation runbook (next step)

## 1) Что уже есть

- Продуктовый план и roadmap.
- API спецификация + OpenAPI контракт.
- Схема БД и SQL-миграции.
- Протокол invite-only и Sprint 1 backlog.

## 2) Что делать команде в первую очередь

1. Подключить OpenAPI контракт в backend как source-of-truth.
2. Применить миграции `0001` и `0002` в dev-окружении.
3. Реализовать `POST /invites/redeem` через `redeem_invite_atomic`.
4. Сделать интеграционный тест гонки (2 параллельных redeem на один токен).
5. Включить rate limiting на `/invites` и `/invites/redeem`.

## 3) Минимальные acceptance criteria

- Пользователь не ищется по логину/телефону/нику.
- Один invite token активируется только один раз.
- Повторный redeem возвращает корректную бизнес-ошибку.
- При сетевых гонках не создается дубликат контактов.

## 4) Технические проверки перед релизом MVP

- Проверка p95 задержки отправки текста в online-online сценарии.
- Проверка восстановления websocket-соединения.
- Проверка безопасности: токены не логируются полностью.
- Проверка удаления/редактирования сообщений на клиенте.

## 5) Что добавить в CI

- OpenAPI lint + schema validation.
- SQL migration dry-run в чистой PostgreSQL.
- Интеграционный тест на атомарный redeem.
- Проверка markdown/yaml линтерами.


## 6) Операционный запуск проверок

- Локально одной командой: `bash scripts/full_local_check.sh`
- Через Make:
  - `make validate`
  - `make pg-up && make pg-checks`
  - `make pg-down`

Это обеспечивает единый воспроизводимый контур для проверки миграций и invite-redeem функции перед merge.
